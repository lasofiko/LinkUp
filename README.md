# LinkUp

## Второй спринт

Общий контракт реакций, названия и границы задач команды находятся в
[docs/sprint-2-contracts.md](docs/sprint-2-contracts.md). Перед началом задачи
синхронизируйте свою ветку с `dev` и используйте типы из `internal/interaction`:
это исключает две разные реализации состояния пары.

Проверка локально:

```sh
gofmt -w <изменённые-go-файлы>
go build ./...
go test ./...
go vet ./...
```

## Ограничения выдачи (контракт B)

`usecase.FilterPairCandidates` принимает результат прежнего поиска
`matching.MatchCandidates` и общий `interaction.Reader`. Порядок поиска,
город и общие интересы сохраняются. Исключаются сам пользователь,
недоступные кандидаты, исходящие лайки и взаимные лайки (match).
Чтение не изменяет состояние; ошибки возвращаются вызывающему коду.
Пустой успешный результат — non-nil slice; интересы копируются.

| Состояние | Выдача A | Выдача B |
|---|---|---|
| До лайков | B виден | A виден |
| A лайкнул B | B скрыт | A виден |
| B ответил лайком | B скрыт | A скрыт |
| Повторные команды | Без изменений | Без изменений |

Здесь A и B — пользователи. Повтор принятого лайка не меняет состояние
согласно `interaction.ApplyLike`. В текущем общем плане контракт A отвечает
за поиск, C — за `React`, D Арины — за состояние и память. Реализаций
`React` и общего `interaction.Store` пока нет: при интеграции фильтру и
команде необходимо передать один экземпляр Store. Старый
`RestrictedDiscoveryService` сохранён для совместимости и читает прежние
`Likes`/`Matches`; он ещё не подключён к новому состоянию пары.

Новый путь B: `usecase.NewPairDiscoveryService(matching.NewDiscoveryService(profiles), store)`.
Метод `Discover(ctx, userID)` сначала выполняет прежний поиск, затем читает
актуальное состояние каждой пары из переданного Store. Передайте этот же `store`
команде `React`: отдельные списки `Likes`/`Matches` этому сервису не нужны.
Интеграционный тест проверяет выдачу до лайков, после сохранения исходящего
лайка, после взаимности и после повторов через один экземпляр `interaction.Store`.

GitLab CI проверяет форматирование новых файлов B, сборку, тесты и vet.
Полная проверка `gofmt -l .` пока выявляет существующие файлы; массовое
форматирование требует отдельного согласования, чтобы избежать конфликтов
с работой команды.
