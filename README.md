## Ограничения выдачи (контракт B)

`usecase.FilterPairCandidates` принимает результат прежнего поиска
`matching.MatchCandidates` и общий `interaction.Reader`. Порядок поиска,
город и общие интересы сохраняются. Исключаются сам пользователь,
недоступные кандидаты, исходящие лайки и взаимные лайки (match).
Чтение не изменяет состояние; ошибки возвращаются вызывающему коду.
Пустой успешный результат — non-nil slice; интересы копируются.

| Состояние | Выдача A | Выдача B |
|---|---|---|
| До лайков | B виден | A виден |
| A лайкнул B | B скрыт | A виден |
| B ответил лайком | B скрыт | A скрыт |
| Повторные команды | Без изменений | Без изменений |

Здесь A и B — пользователи, которые соответствуют обычным условиям поиска:
доступны, находятся в одном городе и имеют общие интересы. Односторонний
лайк скрывает получателя только у отправителя; входящий лайк сам по себе
не исключает отправителя из выдачи получателя. После ответного лайка
возникает взаимность, и оба пользователя исключаются из выдачи друг друга.
Повтор принятого лайка при сохранении допустимости действия не меняет
состояние и выдачу и не вызывает `Save`.

Команда `usecase.ReactService.React` использует существующие правила
допустимости и `interaction.ApplyLike`; успешное изменение возвращается
только после сохранения. При ошибке чтения выдача возвращает ошибку;
при ошибке записи реакции команда возвращает ошибку и нулевой результат.
В текущем общем плане контракт A отвечает за поиск, C — за реакции,
D Арины — за состояние и память. Реализации общего `interaction.Store`
пока нет: при интеграции фильтру и команде необходимо передать один экземпляр
Store. Старый
`RestrictedDiscoveryService` сохранён для совместимости и читает прежние
`Likes`/`Matches`; он ещё не подключён к новому состоянию пары.

Новый путь B: `usecase.NewPairDiscoveryService(matching.NewDiscoveryService(profiles), store)`.
Метод `Discover(ctx, userID)` сначала выполняет прежний поиск, затем читает
актуальное состояние каждой пары из переданного Store. Передайте этот же `store`
команде `React`: отдельные списки `Likes`/`Matches` этому сервису не нужны.
Интеграционный тест проверяет выдачу до лайков, после сохранения исходящего
лайка, после взаимности и после повторов через один экземпляр `interaction.Store`.

GitLab CI и GitHub Actions проверяют форматирование всего репозитория
через `gofmt -l .`: непустой вывод завершает проверку с кодом 1 и печатает
список файлов. Ошибка самой команды тоже приводит к отказу проверки.
Также настроены `go build ./...`, `go test ./...` и `go vet ./...`.
Для исправления форматирования используйте `gofmt -w <пути-к-файлам>`.

## Команда реакции (контракт C)

`usecase.ReactService.React(ctx, fromUserID, toUserID)` выполняет направленный Like между двумя пользователями и возвращает `interaction.State` и `error`.

Зависимости передаются через конструктор `NewReactService`: чтение пользователей, чтение профилей и общее `interaction.Store`.

Последовательность команды:

1. Проверить контекст и загрузить отправителя, кандидата и профиль кандидата.
2. Сформировать канонический ключ пары через `interaction.NewPair`.
3. Загрузить состояние пары через `Store.Load`. Отсутствующая пара (`found=false`) считается начальным состоянием.
4. Проверить допустимость через `domain.CheckCandidateEligibility`, переиспользуя правила контракта C из ЛР1.
5. Применить чистый переход `interaction.ApplyLike`.
6. Вызвать `Store.Save` только при `changed=true`.

### Ошибки и повторы

| Ситуация | Поведение |
|---|---|
| Первый допустимый лайк | Новое состояние сохраняется |
| Принятый повтор | Возвращается текущее состояние без `Save` |
| Отсутствие пары | Используется начальное состояние |
| Отсутствие пользователя или профиля | Возвращается ошибка, запись не выполняется |
| Недоступный кандидат или недопустимое действие | Бизнес-отказ без записи |
| Технический отказ чтения | Операция прекращается, запись не выполняется |
| Ошибка `Save` | Возвращаются нулевой `State` и ошибка |

Ошибки зависимостей оборачиваются через `%w`, поэтому исходная причина доступна через `errors.Is` и `errors.As`.

Результат успешен только при `error == nil`. Повтор лайка при неизменных условиях не создаёт дополнительную запись.

### Проверка

Тесты команды находятся в `internal/usecase/react_test.go` и покрывают успешный лайк, ответный лайк, повтор, недопустимые действия, отсутствие обязательных данных, отказ каждого чтения, ошибку `Save` и повторную попытку после устранения ошибки.

```sh
go test ./internal/usecase -run "^TestReact" -count=1
```

Интеграционная проверка с общей memory-реализацией `interaction.Store` выполняется после подключения хранилища контракта D.
