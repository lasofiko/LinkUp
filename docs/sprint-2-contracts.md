# Sprint 2: общий контракт реакций

Этот документ — единственный источник имён и границ между задачами. Новая логика
реакций живёт в `internal/interaction`; старые `matching`, `usecase` и web-пакеты
не переименовываем во время спринта.

## Модель

Одна пара имеет канонический ключ `interaction.Pair`: меньший идентификатор всегда
в `FirstUserID`. `interaction.State` хранит два независимых направления:
`FirstLikesSecond` и `SecondLikesFirst`. Взаимность возникает, когда оба значения
истинны. Повтор уже принятого лайка — успешная операция без изменения состояния.

| Сценарий | Записей пар | Лайков в паре | Взаимность |
| --- | ---: | ---: | --- |
| нет реакции | 0 | 0 | нет |
| первый лайк | 1 | 1 | нет |
| ответный лайк | 1 | 2 | да |
| любой повтор | 1 | 2 | да |

## Ответственность

| Контракт | Владелец | Использует | Не меняет |
| --- | --- | --- | --- |
| A: поиск и сценарий | Ваня | `matching.MatchCandidates`, B, demo | правила ранжирования первого спринта |
| B: выдача | Соня | `interaction.Reader` | переход состояния и `Save` |
| C: команда реакции | Оля | `interaction.Store`, проверку допустимости | фильтрацию поиска |
| D: состояние и память | Арина | `State`, `ApplyLike`, `Store` | HTTP и поиск кандидатов |

## Имена, которые не меняем

- идентификаторы: `userID`, `candidateID`, `fromUserID`, `toUserID`;
- состояние: `Pair`, `State`, `IsMutual`, `HasLike`;
- хранилище: `Reader.Load`, `Store.Save`;
- чистый переход: `ApplyLike`;
- команда Оли: `React` возвращает результат и ошибку; `Save` вызывается только при
  `changed == true`.

## Порядок общего сценария

1. A получает кандидатов через прежний `MatchCandidates`.
2. B читает состояние пары и исключает пользователя, его исходящие лайки и взаимности.
3. C загружает необходимые данные, проверяет допустимость, вызывает `ApplyLike`.
4. C сохраняет `next` только если переход вернул `changed=true`.
5. A показывает выдачу и состояние после каждого шага в demo.

## Ошибки

Отсутствующая пара — нормальное состояние, которое `Load` возвращает как
`found=false`; это не ошибка. Ошибка чтения/записи — техническая и должна
оборачиваться через `%w`, чтобы работали `errors.Is` и `errors.As`. Бизнес-отказ
не вызывает `Save`. При ошибке `Save` команда возвращает нулевой успешный результат,
а хранилище остаётся прежним.

## Проверки перед PR

```sh
gofmt -w <изменённые-go-файлы>
go build ./...
go test ./...
go vet ./...
```

CI завершится ошибкой, если `gofmt -l` найдёт неотформатированный Go-файл,
изменённый в PR или push. Уже существующий неотформатированный код выносится в
отдельную задачу, чтобы его массовое форматирование не создавало конфликты в
работающих ветках.
