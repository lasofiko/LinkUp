# Sprint 4: блокировка пользователя

`PUT /v1/me/blocks/{targetID}` берёт actor из `X-Demo-User` middleware.
Положительные ID обязательны, тело и query пусты. Неизвестный участник —
404 `not_found`, неверный ввод — 400 `invalid_request`, блокировка себя —
409 `invalid_transition`. Повтор возвращает 200 без новой записи.
Успех: `{"target_id":2,"blocked":true,"mutual":false}`.

Блокировка пары симметрична: после неё никто из двух пользователей не видит
другого в discovery и ни одно направление нового лайка не принимается
(403 `pair_blocked`). Старые направленные лайки остаются для истории, но
`IsMutual()` становится false. У блока нет операции отмены.

Контракт `usecase.BlockStore.Block(ctx, pair)` требует атомарно записать
блокировку и деактивировать match, используя канонический `interaction.Pair`
и тот же протокол блокировки пары, что `ReactService.React`. Текущий
memory-store выполняет это одним изменением состояния под одним lock.
PostgreSQL-реализация и её миграции принадлежат отдельной задаче команды;
она должна использовать транзакцию и проверяться интеграционными тестами
отката при ошибке между двумя действиями. Подмена этого теста memory-тестом
не подтверждает поведение PostgreSQL.
